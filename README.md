# 微信搭楼自动玩家

适用于 Windows 电脑微信小程序“今天盖楼了吗”。程序读取屏幕中的方块与楼顶，通过轨迹预测安排鼠标点击。它不读取游戏内存，也不修改小程序。

## 开始使用

1. 安装 64 位 Python 3.13。首次使用双击 `install.bat`；依赖安装在本目录的 `.venv`，不修改其他 Python 环境。
2. 打开微信游戏，将游戏窗口完整放在主显示器内，手动开始一局。
3. 双击 `start.bat`，回到游戏窗口，按 **F8** 开始自动放置。再次按 F8 暂停，按 **Esc** 退出。
4. 首次运行会以整个游戏窗口为识别区域，选择画面内的空白位置点击。程序每次落地更新校准参数。

游戏窗口应保持原位置、尺寸及前台状态。切换窗口、移动窗口、出现结算或复活弹窗会使程序暂停；不会点击分享、复活或其他页面按钮。重新开始一局后按 F8 恢复。窗口移动后重启程序会重新绑定区域。

需要单独校准时，开始新一局后运行 `calibrate.bat`，回到游戏按 F8。校准模式完成三次可观测落地后退出；统计与参数在日志中，不代表所有参数都已达到相同精度。

## 命令行

在本目录中运行：

```powershell
.\.venv\Scripts\python.exe -m towerbot play
.\.venv\Scripts\python.exe -m towerbot play --setup --preview
.\.venv\Scripts\python.exe -m towerbot calibrate
.\.venv\Scripts\python.exe -m towerbot replay "C:\path\game_sample.mp4" --annotated
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

`--setup` 先框选游戏画面，再在预览图中选择一个正常游戏期间可点击的空白点。选择后回到原游戏窗口再按 F8。`--preview` 显示检测框和预测落点；预览窗口本身不能遮挡游戏，也不要让它保持焦点。

其他参数：`--seconds 60` 限制运行时间；`--stop-on-dialog` 在结算弹窗出现后退出；`--fps 120` 设置采集目标帧率；`--config path.json` 使用独立配置。`--auto-arm` 供受控测试使用，启动时游戏必须已经在前台。默认不会自动开始点击。

首版实测环境为主显示器上的单个微信游戏窗口。其他显示器的桌面坐标转换尚未做实机验证，请将游戏移至主显示器运行。

## 算法

画面宽度统一到 720 像素。轮廓检测定位白色空心方块，颜色分割定位最上方已落楼层，并跟踪提示框。位置、宽度和倾角逐帧更新，背景、文字和遮罩不作为方块。

程序先观察每个新方块至少 0.8 秒，用最近约 1.2 秒的轨迹拟合摆动中心、幅度、相位和频率；频率随每一层重新识别。短时二次模型保留用于运动阶段判断和回归对照，楼顶使用短时线性模型。预测释放时刻的方块位置，加上释放后的小幅横漂，与预计接触时刻的目标位置对齐。下落时间来自高度差及在线估计的屏幕加速度，不使用释放前横向速度进行完整弹道外推。模型无法可靠拟合时等待，不强行点击。

倾斜把楼顶推向屏幕边缘时，检测覆盖画面两侧。同一方块短暂移出屏幕后保留周期轨迹，回到画面并重新确认位置后再安排点击；失踪超过 2 秒或确认新方块后清空轨迹。下落判断会扣除沿倾斜横梁运动造成的竖向速度。落地后楼顶快速摆动时先等待，避免远期位置外推误差导致连续过度纠偏。

鼠标输入按预测释放时间减去等效输入延迟提前发出。延迟从输入时间戳与下降轨迹拟合估计，不是操作系统或游戏内部的直接计时。使用独立可取消定时器，过期计划直接跳过。每个方块最多点击一次，等待新方块生成后才允许下一次点击。

`config.json` 保存区域、点击点及校准值。左右运动分别维护小幅位置偏差修正，减少长期误差。识别或预测不可靠时等待下一次经过中心，不强行下落。

### 倾斜补偿

通过起重机长立柱识别建造轴线，并由立柱角度测量整体倾斜。控制器结合楼顶相对轴线的偏移、倾角和角速度，选择具有回正作用的落点偏置。单次偏置不超过较窄方块宽度的 18%，并要求预测误差范围内仍有至少 60% 的较窄方块受到承托。

每次补偿后记录实际偏移与倾角变化，在线更新位置偏移对倾角的响应系数。接近平衡时使用死区停止小幅来回修正；有意纠偏的偏置会从输入误差校准中扣除，避免被误学成点击误差。这个反馈可以减小整体倾斜；已经放置的楼层不会被移动回原位。

## 日志与复现

每次运行产生独立的 `runs/时间戳/`：

- `frames.jsonl`：观测时刻、识别几何、状态、预测与处理耗时。
- `events.jsonl`：实际点击、跳过计划、落地、暂停原因。
- `summary.json`：有效处理帧率、耗时分位数、落地计数和校准参数。
- `status.json`：每秒更新当前状态和等待原因；逐帧日志也保存 `reason`。
- `context_*.jpg`、`final_*.jpg`：结算前后的最近画面。
- 离线使用 `--annotated` 时生成 `annotated.mp4`。

日志中的 `observed_landings` 是程序确认的落地数量，不能代替游戏 HUD 分数。`floors` 是当前画面检测到的楼层矩形数，也不是总楼层。真实成绩以游戏画面为准。

视频回放不会发送输入。它可验证识别与预测，不能模拟改变点击时机后的游戏，也不能据此宣称达到某个高度。验收记录见 `VALIDATION.md`。

## 常见问题

- **找不到窗口：**打开标题为“今天盖楼了吗”的小程序；同名窗口只能有一个。
- **按 F8 不开始：**先点击游戏窗口的标题栏使其获得焦点，再按 F8；查看终端中的暂停原因。
- **窗口移动后暂停：**退出后重新启动，必要时加 `--setup` 重选。
- **输入失败：**微信和程序应使用相同权限级别，通常都以普通用户运行。
- **始终等待：**查看预览是否正确标记方块与顶层；缩放、主题变化或严重倾斜可能超出当前识别范围。
- **倾斜后停住：**查看最新运行目录的 `status.json`。`block_not_visible` 表示方块暂时出屏，`motion_fit_unavailable` 表示轨迹不足，`tower_still_moving` 表示等待楼体摆动减弱，`support_clipped` 表示承托面被屏幕边缘截断。前几种情况在观测恢复后自动继续；承托面出屏时不能可靠操作，也不会把下面的楼层误作楼顶。`window_not_focused` 表示失焦暂停，回到游戏按 F8 恢复。
- **机器变慢：**关闭预览，保持游戏无遮挡；提高采集设置不会提高游戏自身刷新率。
